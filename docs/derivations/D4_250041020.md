# D4 — Why Prefix Differences Cannot Recover Range Maximum

**CS 253 / MA 253 · Project 5: Aggregates a Fenwick Tree Cannot Support**  
**Oracle owner:** Kasireddy Pranav Karthik · **Roll no.:** 250041020

## Statement

Answering a range query from two prefix aggregates by taking a prefix difference requires an inverse (or, at minimum, a cancellation operation) for the aggregate. The maximum operation has no such inverse. Therefore, in general, the maximum on `[l, r]` cannot be recovered from only the two prefix maxima on `[1, r]` and `[1, l-1]`.

## Definitions and notation

For an array `a[1..n]`, define the prefix maximum

`P(k) = max{a[i] : 1 <= i <= k}`, and define `P(0) = -infinity`.

The range-maximum query is

`M(l, r) = max{a[i] : l <= i <= r}`.

The operation `max` has identity `-infinity`, since `max(x, -infinity) = x`.

## The inverse step that works for sums

For sums, let `S(k) = a[1] + ... + a[k]`. Then

`S(r) = S(l-1) + (a[l] + ... + a[r])`.

Since addition has an inverse, subtracting `S(l-1)` gives the desired range sum:

`a[l] + ... + a[r] = S(r) - S(l-1)`.

The key step is cancellation of the contribution from the first `l-1` positions.

## Why the same step fails for maximum

Suppose we try to imitate the sum formula and seek a value `x` such that

`max(P(l-1), x) = P(r)`.

Knowing `P(l-1)` and `P(r)` does not determine `x`. If `P(l-1)` is already equal to `P(r)`, then every `x <= P(r)` satisfies the equation. The equation therefore has many possible answers, rather than a unique range maximum.

Consider two arrays:

| Array | P(1) | P(2) | Maximum on [2,2] |
|---|---:|---:|---:|
| [5, 3] | 5 | 5 | 3 |
| [5, 4] | 5 | 5 | 4 |

Both arrays produce exactly the same prefix information: `P(1)=5` and `P(2)=5`. Yet their range maximum on `[2,2]` differs (3 versus 4). Thus no method that receives only `P(1)` and `P(2)` can always determine the answer. The earlier maximum hides the smaller values that follow it.

## Algebraic statement: maximum has no inverse

A two-sided inverse for an element `x` under `max` would require some `y` such that

`max(x, y) = -infinity`.

For any finite `x > -infinity`, `max(x,y) >= x > -infinity` for every `y`. Hence no such `y` exists.

More directly, `max` is not cancellative:

`max(5, 3) = max(5, 4) = 5`, even though `3 != 4`.

The exact failing step is cancellation of the prefix contribution `P(l-1)`. Unlike addition, maximum cannot remove an earlier value once it has dominated the prefix.

## Where this is used in the project

This explains why a standard sum-style Fenwick approach based on prefix differences does not provide arbitrary range-maximum queries. The Oracle does not use prefix differences: `OracleMaxCount` scans the requested interval directly, while `OraclePrefixMax` scans positions `1` through `r`. These simple `O(r-l+1)` and `O(r)` scans provide independent reference answers for differential testing.

Relevant implementation: `oracle/oracle.cpp`, functions `OracleMaxCount::query_max_count` and `OraclePrefixMax::query_prefix_max`.

## Conclusion

Prefix subtraction works for sums because addition has an inverse and permits cancellation. Maximum has no inverse and is not cancellative; the same pair of prefix maxima can correspond to different range maxima. Therefore, arbitrary range maximum cannot be recovered from two prefix-maximum values by a prefix-difference formula.

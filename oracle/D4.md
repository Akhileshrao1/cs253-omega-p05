# D4 — Why maximum cannot be answered by prefix differences

## Claim

A range sum can be recovered from two prefix sums because addition has an inverse:
\[
\operatorname{sum}(l,r)=P(r)-P(l-1).
\]
There is no corresponding operation that recovers an arbitrary range maximum from two prefix maxima.

## Exact failed step

For sums, the prefix value is
\[
P(k)=a_1+a_2+\cdots+a_k.
\]
Subtracting \(P(l-1)\) cancels the contribution of positions before \(l\).

For maximum, define
\[
M(k)=\max(a_1,a_2,\ldots,a_k).
\]
The tempting analogue would try to combine \(M(r)\) and \(M(l-1)\) to obtain
\(\max(a_l,\ldots,a_r)\). This fails because `max` has no inverse: once an earlier
large value has become the prefix maximum, the prefix result does not record
whether that value occurred before or inside the requested range, nor what the
next-largest value was.

## Counterexample proof

Consider the two arrays
\[
A=[10,5,8], \qquad B=[10,7,9].
\]
Their prefix maxima are identical:
\[
M_A=[10,10,10], \qquad M_B=[10,10,10].
\]
However, on the range \([2,3]\),
\[
\max(A_2,A_3)=\max(5,8)=8,
\]
while
\[
\max(B_2,B_3)=\max(7,9)=9.
\]

Thus the complete prefix-maximum information is identical for the two arrays,
but the required range answers differ. Any method that uses only those prefix
maxima must produce the same answer for both arrays, so it must be wrong for
at least one. Therefore no general prefix-difference/inverse method can answer
range maximum queries.

## Conclusion

The failure is not a weakness of a particular implementation. It is algebraic:
maximum is associative and has an identity (so it forms a monoid), but it has no
inverse operation. A segment tree can answer range maximum by combining
canonical pieces without needing an inverse.
